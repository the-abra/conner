# CONNER Architecture

This document describes the internal workings and cryptographic design of the CONNER messaging system.

## 1. Cryptographic Protocol

CONNER utilizes a multi-layered encryption approach to ensure Zero-Knowledge privacy:

- **Session Encryption**: Upon connection, the client and server perform an initial handshake to establish a shared session key. All traffic between the client and server is encrypted using this key (ChaCha20-Poly1305).
- **Group Encryption (E2EE)**: Messaging within a room is protected by a 256-bit **Room Key**. This key is generated by the server during join/leave events and distributed to authorized members.
- **Message Integrity**: All chat content is encrypted with the Room Key (AES-256-GCM) before being sent to the relay. This ensures the server can relay messages without being able to read their content.
- **Identity Verification**: Clients use Ed25519 signing keys to authenticate their messages. Public keys are exchanged and verified by members to prevent impersonation.

## 2. Relay Architecture

CONNER operates as a **Blind Postman Relay**:
- **Metadata-Only Awareness**: The server knows who is connected but has no access to the content of the communication.
- **Ephemeral Keys**: The Room Key is kept in server RAM only for distribution and is wiped as soon as the rotation is complete.
- **Binary Framing**: A custom length-prefixed framing protocol ensures efficient and reliable data streaming over high-latency networks like Tor.

## 3. Connectivity Modes

The system is designed to be transport-agnostic:
- **Tor Mode**: Utilizes an embedded Tor engine to create an Onion Hidden Service for the server and routes client traffic through a SOCKS5 proxy. This provides maximum anonymity and NAT traversal.
- **Direct Mode**: Allows for direct TCP connections between clients and servers for use in local networks or where Tor is not required.

## 4. Stability & Resilience

- **Heartbeat System**: To prevent connection drops on "idle" Tor circuits, the client and server exchange PING/PONG heartbeats every 30 seconds.
- **Zero-Dependency**: The entire platform is built in Go with an embedded Tor motor, requiring no external dependencies or system configurations to operate securely.
- **Panic Switch**: The `/burn` command provides a quick way to wipe local identity keys and terminate the session, ensuring no forensic trace of the user's identity is left behind.
